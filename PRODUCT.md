# 0.0 / Life OS — продуктовий та дизайн-бриф

## Що це за продукт

AI-асистент "Life OS" — застосунок, що адаптує свій функціонал під **обрану професію користувача**. Універсальні модулі (календар, фінанси, здоров'я, AI-асистент) лишаються постійними; вкладка **"Робота"** повністю змінює вміст залежно від профілю: Трейдер отримує торговий журнал і економічний календар, IT-спеціаліст — Kanban-дошку, спринти, code review.

Асистент працює **проактивно** — не тільки відповідає на запити, а сам помічає патерни (наприклад, високий screen time напередодні) і повідомляє про це наступного дня.

Бренд: наразі "0.0" (Telegram/Instagram/Substack під цією назвою), робоча назва застосунку — "Life OS". Фінальна назва не затверджена (розглядались декілька альтернатив: Orbit, Kairos, Pulse, Термо та інші — рішення відкладене).

---

## Навігаційна структура (5 вкладок знизу)

1. **Головна** — дашборд: AI-інсайт, погода, події сьогодні, тижневий баланс (фінанси/ринок), прев'ю модулів професії
2. **Календар** — особисті події, повторювані події, категорії (Особисте/Робота), тривалість/весь день
3. **Баланс** — сегменти Здоров'я / Фінанси
4. **Асистент** — окремий чат на всі вкладки
5. **Робота** — адаптивна за професією (окремий верхньорівневий екран-таб, не список угод напряму — див. нижче)

## Дизайн-система (актуальна, замінила Deep Forest)

Проєкт перейшов зі старої темної теми "Deep Forest" на нову світлу тему — рішення прийняте вже в процесі розробки. Стара темна тема (8 темних + 3 світлими варіантами) лишається як довідкова, але поточний фокус розробки — світла версія нижче.

Токени поточної теми:
- `bg`: `#f6f1e6` (фон екрана, теплий кремовий)
- `card`: `#ffffff` (картки)
- `line`: `#eee6d8` (тонка рамка/розділювачі)
- `ink`: `#1f2018` (основний текст, майже чорний теплий)
- `dim`: `#8d8878` (другорядний текст)
- `faint`: `#b3ad98` (приглушений текст/лейбли)
- `grn`: `#3f6b43` / `#4f7a52` (прибуток, позитив — функціональний колір, не декоративний)
- `red`: `#a04430` (збиток, негатив)
- `gold`: `#b58b3a`
- `blue`: `#3c6ea5`

Типографіка: Onest (основний текст, заокруглений sans), Unbounded (великі числа, суми, hero-значення — виразний акцентний стиль для важливих цифр).

Важливе правило кольору (з довгого досвіду ітерацій команди): НЕ використовувати яскраві насичені кольорові фони як декорацію (hero-картки, бейджі) — це "муляє око". Темні/нейтральні hero-картки (`linear-gradient(135deg, #2a2620, #1f2018)`), колір лишається тільки функціональним сигналом (зелений = прибуток, червоний = збиток).

Форма: великі радіуси заокруглення (18-30px на картках, 32px на "екрані телефону"), м'які тіні в тон кольору картки (не чорні), тонка 1px рамка замість товстих бордерів.

## Функціонал по розділах

### Головна
- AI-картка (проактивний інсайт, оновлюється за різною логікою залежно від джерела — див. "Асистент" нижче)
- Погода (поточна + погодинний прогноз)
- Події сьогодні
- Тижневий баланс: фінанси (витрати тижня, календарний пн-нд з обнуленням) + показник здоров'я
- Кастомізація: користувач може ховати/показувати/переставляти віджети (режим редагування — довгий тап — хрестики на блоках, "+ Додати віджет" — плитка в потоці контенту)

### Здоров'я (сегмент Балансу)
- Вибір активності (біг/тренування/розтяжка)
- Показники дня: сон, кроки, пульс, screen time, вода (повністю локальна функція, без API — ручний ввід кнопками +250мл/+500мл, з перемикачем увімкнути/вимкнути)
- Журнал самопочуття — настрій + вільний текст, підказки-заготовки
- Інтеграція з Apple Health/Screen Time — заплановано, ще не підключено (потребує Capacitor + HealthKit)

### Фінанси (сегмент Балансу)
- Категорії витрат, транзакції, бюджети
- Інтеграція з Monobank API — в процесі, відомі баги: некоректний розрахунок тижневих витрат (мало бути пн-нд з обнуленням), неузгодженість валюти між Головною й вкладкою Фінансів
- Мультивалютність: транзакції показуються у валюті картки, з якої списалась; підсумковий баланс конвертується у валюту застосунку за замовчуванням

### Робота — Трейдер (три рівні глибини, це важливо)
1. Вкладка "Робота" (верхній рівень) — hero-баланс активного рахунку (нейтральний темний, без зеленого), сітка модулів-плиток: Журнал угод (з міні-графіком), Економічний календар (найближча важлива подія), Ризик-калькулятор, Статистика
2. Журнал угод (другий рівень, куди веде плитка з п.1) — список рахунків з індикатором синхронізації біржі (зелена крапка = свіжі дані, жовта пульсуюча = синхронізується, сіра = давно не оновлювалось), 4 показники (Net P&L / Win rate / P.Factor / Угод), графік (Крива/Стовпчики/Просадка) з селектором періоду (Місяць/Квартал/Рік), два режими перегляду: Список і Календар (місячна сітка, кожен день клітинки — зелена/червона/нейтральна за результатом дня), фільтри (Всі/За планом/Порушення/Відкриті/Закриті)
3. Нова угода (третій рівень) — Long/Short, Відкрита/Закрита, За планом/Порушив, Ринок/Інструмент/Дата-час/Сетап, ціни Вхід-Стоп-Тейк з живим розрахунком R:R, Лот/Ціна закриття, Комісія/Своп, Сетап/теги з кастомним тегом, Логіка входу/нотатки (вільний текст + підказки), скріншот графіка, жива картка розрахунку P&L знизу

Відомий баг (в роботі): дані з підключеної біржі (Bybit) не заповнюють стоп/тейк/комісію/своп при імпорті угод — ці поля коректно зберігаються тільки при ручному вводі. Причина — ймовірно неповний мапінг відповіді API біржі на внутрішню модель угоди.

Архітектурна вимога: жорстке розділення рахунків на manual і exchange-synced (з полями `exchangeId`, `lastSyncedAt`, `syncStatus`); синхронізація запускається при кліку на чіп рахунку, з порогом ~2 хв між запитами до того самого рахунку, щоб не спамити API біржі.

### Робота — IT/Розробник
Kanban-дошка задач, прогрес спринтів, статус CI/білдів, черга Code Review (PR, що чекають рев'ю користувача), фокус-сесії/Pomodoro.

### Асистент
- Проактивні інсайти з різною частотою оновлення за джерелом:
  - Календар — дебаунс після серії редагувань (5-10 хв тиші)
  - Фінанси — максимум 1-2 рази на день
  - Торговий журнал — тільки при закритті позиції (не при відкритті/редагуванні)
- Плаваючі міні-асистенти в Календарі й Роботі: показують керовані дані, ніколи не викликають API просто на відкриття панелі — тільки на реальний запит користувача чи реальне оновлення джерела
- Повідомлення користувача в міні-асистенті персистяться (не губляться при перезаході в застосунок)

## Технічний стек і зовнішні інтеграції
- Frontend: Next.js, Zustand для стору, Recharts для графіків
- AI: Claude API (Anthropic), server-side only
- Фінанси: Monobank Personal API (безкоштовний, ліміт 1 запит/60сек на акаунт)
- Трейдинг: Bybit API, MT5 (в розробці)
- Здоров'я: Apple HealthKit через Capacitor (заплановано)
- Дизайн-система підключена через CSS-змінні/`data-theme`, підтримує перемикання тем
